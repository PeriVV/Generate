## 1.2 系统概述

java智能单元测试工具（以下简称"本工具"）是一款面向 Java 项目的 IntelliJ IDEA 插件，名称为 UnitMind，用于为 Java 方法自动生成 JUnit 5 + Mockito 单元测试。

本工具以 IntelliJ IDEA 右侧工具窗口（Tool Window）为人机交互界面，将单元测试生成过程组织为五个步骤：静态分析结果、测试场景、Mock 策略、测试代码、写入测试文件。用户在编辑器中将光标置于待测方法内，通过编辑器右键菜单或工具窗口启动分析后，工具按步骤完成以下工作：

a）本地静态分析：使用 JavaParser 解析被测方法源码，提取方法信息、参数信息、参数约束、控制流分支和依赖调用，该阶段不调用大模型、不发送任何网络请求；

b）测试场景规划：基于静态分析结果规划正常、异常、边界三类测试场景，用户可在表格中增删、编辑场景；

c）Mock 策略规划：基于字段依赖、静态调用、本类内部调用等分析结果生成静态 Mock 策略，并可选调用大模型生成候选 Mock 策略，由用户选择其一参与生成；

d）测试代码生成：优先使用规则兜底生成一份测试代码，启用大模型时结合静态分析上下文生成更完整的 JUnit 5 + Mockito 测试类；生成后使用当前模块的 SDK 与依赖执行隔离编译校验，编译错误可反馈大模型自动修复；

e）覆盖率闭环：编译通过后可在隔离 JVM 中真实执行测试，通过内置 JaCoCo agent 统计被测方法的行覆盖率与分支覆盖率，未达标时自动补测并修复运行失败，期间以 Oracle 仲裁机制保护测试断言不被随意改写；

f）测试文件写入：将最终测试代码写入项目测试目录，支持新建、追加、覆盖三种模式，追加时以 UnitMind 区域（region）管理历次生成内容，保留用户人工编写的测试代码。

本工具生成的测试代码在写入前始终可编辑，正常写入以"最终文本编译通过"为门禁条件。

## 1.3 文档概述

编写本文档的目的是描述 java智能单元测试工具的功能、运行环境，详细描述软件的安装、启动和使用操作说明，软件的异常处理与恢复等内容，帮助软件使用人员了解软件操作方法，做好产品交付后服务。

# 3 软件综述

## 3.1 软件应用

java智能单元测试工具包括如下功能：

a）生成入口：在编辑器右键菜单提供"UnitMind：生成单元测试"与"UnitMind：测试数据生成配置"两个入口，前者自动打开右侧 UnitMind 工具窗口并立即分析光标所在方法；

b）静态分析：自动定位当前光标所在方法，无法定位时退回到文件中的 public 方法或首个方法；展示方法信息、参数信息、参数约束（来自 if / throw / requireNonNull 判断）、控制流分支、依赖调用五类客观事实；

c）测试场景：按正常（NORMAL）、异常（EXCEPTION）、边界（BOUNDARY）三类规划场景，给出场景名称、触发条件、期望结果与测试方法名，支持新增、删除、编辑与恢复推荐；

d）Mock 策略：并排展示静态分析 Mock 策略与大模型候选 Mock 策略，用户可切换采用哪一份，策略项的生成开关、Mockito 策略、备注均可编辑；

e）测试代码生成与编辑：生成 JUnit 5 + Mockito 测试类，代码区提供 Java 语法高亮、行号与编辑能力，支持复制、还原、按补充要求再次生成；

f）编译校验闭环：使用当前模块 SDK、测试依赖与源码路径对完整测试类执行隔离编译，可修复的编译错误反馈大模型自动修复，修复轮次可配置（默认 5 轮，0–30），环境类错误（模块未配置 SDK、缺少 JUnit 5 / Mockito）不消耗修复轮次；

g）覆盖率闭环：在隔离 JVM 中仅运行本次候选测试类，通过内置 JaCoCo agent 只统计当前选中方法的可执行行与分支；默认目标行覆盖率 90%、分支覆盖率 80%，未达标时按主缺口自动补测，覆盖率探索与失败修复轮次独立配置（默认各 5 轮，0–30）；

h）运行失败修复与 Oracle 保护：测试运行失败时按"测试意图锁定、堆栈定位、根因分类、Oracle 仲裁、最小修改"协议修复，正常/成功场景不会被改写成异常断言；启用"严格 Oracle 准出"后，凡判定需修改断言的修复一律不自动应用，转人工确认；

i）疑似产品缺陷识别：严格门禁确认疑似被测代码（SUT）缺陷时，覆盖率闭环立即停止并保留失败测试与证据，可展开只读的源码缺陷归因分析（置信度、可能位置、根因假设、证据与建议核查项）；

j）测试文件写入：源文件位于 src/main/java 时测试文件写入对应 src/test/java 包路径，否则写入源文件同级 generated-test 目录；支持新建、追加、覆盖三种写入模式，追加时将本次生成内容包裹在 `UnitMind generated tests for <方法名>` region 中，同一方法存在旧 region 时可原子替换；

k）大模型配置：支持任意 OpenAI Chat Completions 兼容接口，可配置 API 地址、模型名称、超时、输出长度、温度、思考模式等，并提供连接测试；

l）测试数据生成配置：按类型配置随机测试数据的最小值、最大值、小数位数、字符串规则与候选值，控制静态分析阶段为参数补充的候选测试数据范围。

java智能单元测试工具性能如下：

a）静态分析在本地完成，不依赖网络，打开面板或重新分析不阻塞 IDE 界面（耗时任务均在后台线程执行）；

b）大模型请求超时时间默认 180 秒，可配置 1–600 秒；

c）覆盖率闭环单轮测试执行超时默认 60 秒，可配置 5–600 秒；

d）编译修复、覆盖率探索、覆盖率失败修复轮次默认各 5 轮，均可配置 0–30 轮。

## 3.3 软件组织和操作概述

本工具为纯客户端插件，无服务端组件。全部功能通过 IntelliJ IDEA 右侧 UnitMind 工具窗口提供。

工具窗口自上而下分为四个区域：顶部标题区显示工具名"UnitMind"、副标题"智能单元测试生成助手"、当前方法与源码位置，右侧提供"设置"与"重新分析"按钮；其下为步骤条，以按钮形式展示五个步骤（静态分析结果、测试场景、Mock策略、测试代码、写入测试文件），当前步骤高亮，完成的步骤标记状态，点击可切换步骤；中部为当前步骤的内容区；底部提供"上一步""下一步""重新分析""写入文件"四个导航与操作按钮。

启动后，在编辑器中将光标置于待测方法内，右键选择"UnitMind：生成单元测试"，工具窗口自动打开并开始静态分析；随后按步骤条依次完成场景确认、Mock 策略选择、测试代码检查与覆盖率闭环，最后在写入步骤将测试文件落盘。

## 3.4 意外事故及运行的备用状态和方式

a）大模型调用失败或超时：按配置决定是否回退到规则生成（设置中"失败时使用规则兜底"，默认开启），保证测试代码页不空白；

b）未启用或未配置大模型：静态分析、场景规划、Mock 策略、规则测试代码生成与写入功能均可独立使用；

c）覆盖率环境错误：模块未配置 SDK、缺少 JUnit 5 / Mockito 依赖等环境问题会直接报告"环境错误"，不消耗修复轮次，不影响测试代码的人工编辑与确认写入；

d）生成过程中断：覆盖率闭环运行中可随时点击"停止"；切换被测方法或点击"重新分析"会自动取消进行中的后台任务。

## 3.5 保密性

本工具的保密性要求：

a）静态分析阶段（方法信息、参数约束展示）只使用本地 JavaParser 分析，不调用大模型、不发送任何网络请求；

b）首次启用大模型时，工具弹出安全提示，明确告知将把当前被测方法源码、静态分析结果和测试场景发送到用户自行配置的大模型接口，需用户确认后方可启用；

c）API Key 优先读取环境变量 UNITMIND_API_KEY，在设置界面输入的新 Key 保存于 IntelliJ PasswordSafe，不写入普通配置文件；

d）本工具资料不得泄露给第三方，因故意或过失造成泄密将追究责任人责任。

# 5 使用软件指南

## 5.1 能力

java智能单元测试工具是 Java 项目单元测试的辅助生成工具，核心能力为：本地静态分析被测方法、规划并管理测试场景与 Mock 策略、生成可编辑的 JUnit 5 + Mockito 测试代码、以编译校验与真实执行覆盖率闭环保障生成质量、将测试文件安全写入项目测试目录。

## 5.2 约定

a）流程约定：生成流程固定为"静态分析结果 → 测试场景 → Mock策略 → 测试代码 → 写入测试文件"五个步骤，后续步骤在前置步骤产生数据后方可进入；

b）失效约定：测试场景或 Mock 策略被编辑后，已生成的旧测试代码立即失效；测试代码被手工编辑后，编译校验状态立即失效，写入前必须重新校验；测试代码或被测源码变化后，已有覆盖率报告标记为失效；

c）门禁约定：正常写入要求最终写入文本编译通过；测试真实执行失败时正常写入被阻止，需修复或明确选择"强制写入"；

d）保留约定：追加写入保留 UnitMind 区域之外的人工测试与 fixture；纯覆盖率改进只接纳新增测试、必要 helper、字段和 import，不改动现有测试脚手架。

### 5.3.3 静态分析结果

### 5.3.4 测试场景

进入本步骤后，工具基于静态分析结果按需规划测试场景，以可编辑表格展示，列包括：生成（是否参与测试代码生成）、场景类型（NORMAL / EXCEPTION / BOUNDARY）、场景名称、触发条件、期望结果（由场景类型推导，只读）与测试方法名，见图 5-4。

场景类型以 _REASON 结尾的行为不可执行的原因说明行，其"生成"开关不生效、期望结果显示"--"。

页面底部提供三个操作按钮：

a）"新增场景"：在表格末尾追加一行自定义场景（默认类型 NORMAL，可编辑），并同步参与后续生成；

### 5.3.7 覆盖率闭环

点击测试代码页的"运行覆盖率"后，工具在不修改被测项目 Maven / Gradle 文件的前提下：

a）将当前被测源码与候选测试编译到临时目录；

b）使用模块 JDK 启动隔离 JVM，只运行本次候选测试类；

c）通过内置 JaCoCo agent 采集数据，只统计当前选中方法源码范围内的可执行行和分支；

d）未达到覆盖率目标（默认行 90%、分支 80%）时，每轮选择一个主缺口和最多四个关联缺口反馈给大模型补测；无增益时自动轮换主目标；

e）采用"最佳候选检查点"策略：只有候选测试编译通过、全部运行成功且覆盖率不下降时才被接纳，否则回滚到最佳可用版本；

f）运行失败修复遵循 Oracle 保护：正常/成功场景不会被改写成异常断言；修改断言类修复受"严格 Oracle 准出"开关控制（见 5.3.9）；

g）疑似真实被测代码缺陷或 Oracle 证据冲突时闭环立即停止，保留原失败测试与 expected/actual/堆栈证据；确认疑似缺陷后额外展示只读的"疑似源码缺陷分析"（置信度、结论、可能位置、根因假设、证据与建议核查项）。

闭环过程与结果在诊断区"覆盖率反馈"组件中实时展示，包括目标（行 xx% / 分支 xx%）、当前候选轮次、逐轮快照（初始 / 补测 N）及行覆盖、分支覆盖进度，见图 5-7。覆盖率终态说明见表 5-3。

表 5-3 覆盖率闭环终态说明

| 终态 | 含义 |
|---|---|
| 已达标 | 行、分支覆盖率均达到目标 |
| 未达标 | 轮次耗尽或无覆盖增益时仍未达标；允许用户确认后写入 |
| 测试失败 | 候选测试存在运行失败；正常写入被阻止 |
| 疑似产品缺陷 | 严格门禁确认疑似被测代码缺陷；保留失败测试与证据，可选择写入作为缺陷复现用例 |
| 需人工确认 | 严格 Oracle 准出模式下模型判定需修改断言；闭环停止，由人工确认 |
| 环境错误 | SDK、依赖等环境问题，闭环不消耗修复轮次 |
| 已失效 | 测试代码或被测源码已变化，报告失效 |
| 已取消 | 用户点击"停止"终止 |

## 5.5 错误、故障和紧急情况下的恢复

a）静态分析失败：页面显示失败原因（如源码使用了高于 Java 17 的语法），修正源码或选择其他方法后点击"重新分析"；

b）大模型调用失败或超时：若开启"失败时使用规则兜底"，自动回退规则生成；否则在测试代码页显示失败原因，可在设置中检查 API 地址、Key 与网络后重试；

c）编译校验未通过：工具自动将标准化后的编译错误反馈大模型修复（默认最多 5 轮，可配置）；仍不能通过时可人工修改代码后"重新校验"，或在写入步骤明确确认后"强制写入"草稿；

d）环境错误：检查模块是否配置 SDK、测试依赖是否包含 JUnit 5 与 Mockito；环境错误不消耗修复轮次，排除后重新校验即可；

e）覆盖率未达标：允许用户确认后写入；可增大探索轮次或调整目标后重试；

f）测试运行失败：正常写入被阻止；按诊断区堆栈修复后重新运行，疑似产品缺陷时保留证据并转人工确认；

g）场景或策略误操作：点击"恢复推荐"恢复推荐场景；Mock 策略可重新生成或切换；测试代码可点击"还原"恢复最近一次生成结果。
