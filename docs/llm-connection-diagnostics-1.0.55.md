# 1.0.55 大模型连接与波动诊断

状态：定向检查通过，最终完整回归、IDEA API 与 Windows 原生验收准备中；尚未交付新包。

## 入口与模式

设置中的“测试连接 / 诊断”打开独立窗口，读取本次尚未保存的配置快照；点击“开始诊断”才发送请求。正常生成仍需在设置中点击“保存”。测试说明会显示请求数量、可能的模型额度消耗和网络等待预算，均可停止。

| 模式 | 请求与用途 | 边界 |
| --- | --- | --- |
| 基础诊断 | 1 次短请求，检查鉴权及聊天响应 | 小探测通过不代表长生成可用；截断、只有推理、无正文等显示提示 |
| 新连接诊断 | 1 次短请求，不复用连接池 | 便于单独观测 DNS、建连和 TLS；系统 DNS 仍可能缓存，不能据此证明发出了 DNS 网络查询 |
| 生成诊断 | 1 次短请求 + 1 次内置小方法生成 | 复用生成提示词、解析协议、思考与输出预算，检查 Java 负载语法；不读取项目源码，不在项目编译/运行，也不代表大项目输入或峰值稳定 |
| 波动观测 | 最多 5 次短请求，完成后间隔 2 秒 | 统计本次成功、提示、失败与耗时分布，不是持续监控或负载压测 |

## 观测与报错

- 真实 HTTP 调用链记录 DNS、建连、TLS、请求发送、响应头、首段数据、首推理、首正文、接收间隔、接收字节、SSE 事件、推理片段、正文字符数及结束原因。接收时点是客户端观测，不能仅凭等待时间认定服务端在排队。
- 显示 HTTP 状态、实际 Content-Type、HTTP 协议、连接复用、连接尝试数、代理类型、服务请求 ID、Retry-After。复用或未完成的阶段写明“未单独测得”，不虚构 0ms；TLS 耗时已包含在建连耗时中，不重复相加。
- 窗口显示当前阶段及持续增长的等待时间，网络暂时没有数据时计时仍继续；可停止并保留已完成观测。关闭窗口或项目会撤销请求；旧轮次回调不能覆盖新轮次或关闭后的窗口。
- 区分 DNS、连接拒绝、TLS、代理认证、HTTP 鉴权/权限/参数、接口或模型不存在、限流、上游故障、网关超时、客户端等待响应头/首段数据/后续数据空闲超时、单次总期限、流中断、无正文、推理无正文、输出截断、协议格式和合成生成负载错误。每项有稳定错误码和对应排查建议。
- HTTP 200 中的 `error` 及 MiniMax `base_resp.status_code != 0` 不再按成功处理；SSE 内服务错误与网络中断分别报错。对数值服务错误码保留原码，不凭未知部署臆测含义。
- 普通生成中的 HTTP 失败和客户端超时也带对应诊断码、建议及服务请求 ID，保留原异常原因与 SocketTimeoutException 类型；正常生成的既有重试策略保留。

## 波动观测的请求与统计规则

诊断使用生产客户端的地址规范化、凭据优先级、参数、超时、代理、流式读取与响应解析，但为了不掩盖首错，诊断请求关闭自动连接重试与自动重定向，并标记为不可重复提交，确保每个计划请求仅发送一次。库中 503/Retry-After:0 也可能触发跟进请求，因此仅关闭连接失败重试不够；依据 [OkHttp 4.9.0 的重试与跟进实现](https://github.com/square/okhttp/blob/parent-4.9.0/okhttp/src/main/kotlin/okhttp3/internal/http/RetryAndFollowUpInterceptor.kt)处理，并用真实 HTTP 请求计数测试验证。

遇到鉴权、配置、参数、重定向或限流等需先修复的问题，停止后续探测；波动观测中的偶发上游失败可继续有限观测。前置短请求失败时不继续发送合成生成。取消和未开始的请求不计入失败率分母；成功率明确包含连通提示，不能解读为生成成功率。耗时中位数对偶数样本取中间两项平均。

## 数据与资源边界

报告与复制内容隐藏当前 Key、Bearer、常见密钥字段、URL 认证与查询参数，不保存请求正文或完整模型回复；仍包含主机、路径、模型和服务请求 ID，分享前需自行确认这些上下文是否可分享。错误摘要限制长度；不能把“隐藏密钥”等同于完整匿名化。

正常 JSON 响应上限 8 MiB、流式原始数据上限 64 MiB，沿用单事件与聚合正文限制。合成生成语法检查限 256 Ki 字符，避免对异常大的诊断回复做无限制本地解析。单次网络总期限仍为配置空闲等待上限的 3 倍，持续心跳也不能无限延长任务；模式总预算在开始前显示，不擅自缩短用户配置来制造成功结论。

## 验证

采用本地真实 HTTP 服务验证阶段观测、偶发 503、429 后停止、Retry-After、HTTP 200 错误负载、空推理元数据、首次与后续等待超时、流内错误、断流、重定向不跟进、503 不重复提交、主动停止、统计与脱敏；同时通过真实 IDEA 插件类加载器验证诊断服务和生成解析。没有访问用户内网或调用付费模型。

最终完整回归、Windows 构建来源、兼容检查与安装包指纹将在验收后补入。用户实际内网的排队、证书、网关或容量问题仍需依据新报告和服务日志确认。
