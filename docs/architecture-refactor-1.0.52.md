## 范围与边界

本轮首先贯通取消链路、建立候选验证证据，再迁移服务和 UI 职责。保留候选独立编译/运行、修复回滚、最终合并文件重新编译/运行及写入时源码/目标文件乐观锁。

- `OperationContext` 绑定发起任务、进度指示器及显式取消信号。HTTP 请求和响应体读取可取消，javac 与构建工具短周期等待，取消不进入规则兜底或网络重试。
- `CandidateIdentity` / `CandidateEvidence` 是不可变快照，绑定源码、测试文本和环境指纹。环境包含有序 classpath、SDK 可执行文件与 release、处理器配置、JVM 参数、运行环境、项目 roots revision、生产依赖源码与构建配置。配置与源码同时关注磁盘和未保存文档；二进制依赖使用路径/大小/修改时间元数据。
- 编译前捕获证据，编译后、JUnit 启动前/执行后和提交写入时复核；候选与最终文件的编译/运行证据必须对应同一身份。配置原值不进入报告或模型上下文。
- `SourceAnalysisService` 承担 PSI/JavaParser 分析与符号补充，生成服务保持原入口。PSI 降级会明确标示约束和分支信息可能不完整。
- `GenerationSnapshotFactory` 负责后台任务输入与结果隔离；`GenerationEvidenceInvalidator` 统一测试编辑后的证据失效规则。
- `TestWriteValidationService` 承担候选验证、合并和最终回归顺序；提交仍在 EDT 的写命令中执行，并重新校验乐观锁及环境快照。
- `WriteModeSelector` 将写入决策与 Swing 对话框分离；`TestExecutionServices` 可注入执行边界。
- `ExecutionEnvironmentSession` 仅在当前任务内复用仍有效的运行环境导出。每个候选和最终文件仍独立编译/执行；不缓存测试通过证明。
- `ossRuleSweep` 独立于普通回归，并要求准备好夹具。探索中的候选失败仍单独编目，不能等同于所有生成场景都成功。规则代码提示明确区分不抛异常与业务断言。
