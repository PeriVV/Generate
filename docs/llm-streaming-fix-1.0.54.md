# 1.0.54 内网 MiniMax 长生成超时修复

状态：本地复现、定向检查、最终完整回归、三个 IDEA 版本 API 检查和 Windows 原生验收全部通过，最终安装包已核对。用户实际内网服务仍需升级后确认。

## 已确认的代码问题与边界

连接测试只请求很短的回复（普通模型 16 token、推理模型 1024 token）；正常生成默认最多 24000 token，显式思考模式至少 32768 token。此前两者都等待完整非流式响应，因此短探测成功不能证明长请求不会遇到客户端空闲超时或网关限制。用户目前仅提供“内网 MiniMax、timeout”，未提供具体时长、响应日志或网关配置；没有访问用户内网，不能据此确定其实际超时发生在哪一层。

另确认两处设置不一致：整类编译修复复制配置时遗漏思考模式；设置内输入新 Key 后的测试优先使用输入值，而保存后运行优先使用环境变量。两者均已修复，测试与运行统一使用环境变量、当前输入、已存凭据的优先级。

## 实现

- 默认对生成、修复、Mock 策略与连接测试请求 `stream=true`，使用同一个传输入口。设置中可以关闭流式，兼容不支持该参数的内网网关；若网关忽略参数并返回完整 JSON，也沿用原解析。不新增从流式自动改为非流式的重复提交；既有覆盖率/修复流程的有界网络重试仍保留。
- 逐条接收 SSE 的 `data:`，正确处理心跳、CRLF、多行事件、分段正文、推理字段和最终完整 message；只使用第一候选正文。收到结束原因后即可完成，不依赖网关额外关闭连接。
- 中途断流或缺少结束原因会丢弃部分输出；`length` 仍按截断拒绝，只返回推理时仍不视为测试代码。保留既有编译、执行与写入门禁。为事件和聚合内容设置大小上限。
- 保留可取消的 HTTP 请求和有界等待：设置值是读写空闲等待上限，单次总上限为其 3 倍；持续心跳也不能无限占用任务。超时提示包含阶段、已用时间、空闲上限、总上限及流式选择，保留原 IO 异常原因，不记录 Key 或提示词内容。
- 连接测试成功弹窗说明这是小请求检查，需点击“保存”才应用设置；内网 MiniMax 名称没有厂商斜杠时，也使用推理探测预算。
- 整类编译修复从完整配置快照派生，保留思考模式、流式选择和其它请求配置。

协议参考 [MiniMax 官方兼容接口文档](https://platform.minimax.io/docs/api-reference/text-openai-api)。文档说明推理会计入输出预算，并提供流式与独立推理内容的参数；内网部署是否转发这些行为仍取决于具体服务与网关。

## 验证方法

本地真实 HTTP 服务复现“短探测成功、长生成无数据超时”，并验证流式心跳及推理片段让同样的慢响应完成；另外验证 SSE 取消与总期限、断流/截断保护，以及 IDEA 真实插件类加载器下的 SSE 探测和生成。使用合成源码与本地测试凭据，不调用用户内网或付费模型。最终结果、Windows 构建来源和安装包指纹见下方。

## 使用边界

流式接收有助于服务持续发送数据时避免客户端空闲超时，但不能绕过模型排队、首个响应等待过久、网关缓冲或网关固定总时限。若升级后仍超时，应根据新的阶段和时长提示核查内网服务，并与网关的超时设置对照；不能仅凭连接测试成功认定生成服务正常。
