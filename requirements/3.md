# Codex 修改要求：修复 JavaParser 不支持 switch expression 和 record 导致生成失败的问题

当前在测试 `DynamicSqlExecutor#resolveTemplate` 方法时，插件生成失败，界面提示：

```text
生成失败。

告警：
(line 88,col 16) Switch expressions are not supported.
(line 101,col 29) Switch expressions are not supported.
(line 220,col 20) Switch expressions are not supported.
(line 386,col 5) Record Declarations are not supported.
```

原因是被测类使用了 Java 新语法：

1. `return switch (...) { case ... -> ... };`
2. `yield`
3. `private record ParsedKind(...)`
4. 局部 `var`

当前 JavaParser 配置或版本不支持这些语法，导致整个 `CompilationUnit` 解析失败，后续参数约束、测试场景、Mock 策略和测试代码都无法生成。

请按以下要求修复。

---

## 1. 提升 JavaParser 语言级别

在 `JavaSourceAnalyzer` 初始化 JavaParser 时，显式设置 Java 语言级别。

优先支持 Java 17。

示例：

```java
ParserConfiguration configuration = new ParserConfiguration();
configuration.setLanguageLevel(ParserConfiguration.LanguageLevel.JAVA_17);

JavaParser javaParser = new JavaParser(configuration);
ParseResult<CompilationUnit> result = javaParser.parse(sourceText);
```

不要继续只用：

```java
StaticJavaParser.parse(sourceText);
```

如果项目仍然使用 `StaticJavaParser`，也必须统一设置配置：

```java
ParserConfiguration configuration = new ParserConfiguration();
configuration.setLanguageLevel(ParserConfiguration.LanguageLevel.JAVA_17);
StaticJavaParser.setConfiguration(configuration);
```

要求：

1. `switch expression` 能正常解析；
2. `record declaration` 能正常解析；
3. `yield` 能正常解析；
4. `var` 能正常解析；
5. 不要因为类中存在 Java 新语法就导致整个插件生成失败。

---

## 2. 升级 JavaParser 依赖

检查 `build.gradle.kts` 中 JavaParser 版本。

如果当前版本过旧，请升级到支持 Java 17 语法的较新版本。

示例：

```kotlin
implementation("com.github.javaparser:javaparser-core:3.25.10")
```

如果项目已经使用 `javaparser-symbol-solver-core`，也同步升级：

```kotlin
implementation("com.github.javaparser:javaparser-symbol-solver-core:3.25.10")
```

注意：

1. 不要同时引入多个不同版本的 JavaParser；
2. 升级后执行 Gradle 编译验证；
3. 如果版本冲突，优先保证插件能编译运行。

---

## 3. 增加解析失败降级机制

即使 JavaParser 仍然解析失败，插件也不能只显示空页面。

请增加降级策略。

### 3.1 JavaParser 解析失败时保留错误信息

如果 JavaParser 解析失败，需要在“概要”页显示：

```text
源码解析失败。

可能原因：
- 当前源码使用了插件暂不支持的 Java 新语法；
- JavaParser 版本或语言级别配置过低；
- 源码存在语法错误。

解析错误：
...
```

不要让其他页面完全空白。

---

### 3.2 使用 PSI 作为兜底解析

如果 JavaParser 解析整个文件失败，则使用 IntelliJ PSI 兜底获取当前方法的基本信息。

兜底至少要能获取：

1. 包名；
2. 类名；
3. 当前方法名；
4. 返回类型；
5. 参数名称；
6. 参数类型；
7. 字段依赖；
8. 方法体文本。

可以用 PSI：

```java
PsiFile psiFile = PsiDocumentManager.getInstance(project).getPsiFile(editor.getDocument());
PsiElement elementAt = psiFile.findElementAt(editor.getCaretModel().getOffset());
PsiMethod method = PsiTreeUtil.getParentOfType(elementAt, PsiMethod.class, false);
```

如果能拿到 `PsiMethod`，则构造一个基础 `MethodModel`，并继续生成测试草稿。

---

## 4. 不要因为整类解析失败影响当前方法

当前用户只选择了 `resolveTemplate` 方法，但插件解析整个类时，因为类尾部的 `record` 报错，导致当前方法也无法生成。

请调整逻辑：

1. 优先用 PSI 定位当前光标所在方法；
2. 拿到当前方法文本；
3. 优先分析当前方法；
4. 如果整类 JavaParser 解析失败，不要直接终止；
5. 当前方法可以解析时，继续生成测试；
6. 当前方法也无法解析时，再展示失败信息。

---

## 5. 对 switch expression 增加分析支持

`resolveTemplate` 中存在这种结构：

```java
return switch (k) {
    case "DM8" -> requireTemplate(...);
    case "POSTGRESQL" -> requireTemplate(...);
    case "TDENGINE" -> requireTemplate(...);
    case "MYSQL" -> requireTemplate(...);
    default -> throw new IllegalArgumentException("Unsupported dataSourceKind: " + kind);
};
```

解析成功后，需要至少识别：

1. `switch` 分支；
2. 每个 `case` 的取值；
3. `default` 分支；
4. `default` 分支中的异常抛出；
5. `requireTemplate(...)` 方法调用；
6. `runtimeRegistry.getJdbcTemplate(...)` 方法调用；
7. `runtimeRegistry.hasConfig(...)` 方法调用。

MVP 阶段不要求完整控制流分析，但不能忽略 `switch expression`。

---

## 6. 对 record 增加兼容处理

当前类中有：

```java
private record ParsedKind(String type, String name) {
}
```

MVP 阶段不要求深入分析 record，但 JavaParser 不能因为 record 存在而失败。

处理要求：

1. 能正常跳过或识别 record；
2. 不要求为 record 生成测试；
3. 不影响当前方法 `resolveTemplate` 的解析；
4. 如果 `ParsedKind parsed = parseKind(kind);` 中使用了 record 的访问器，例如 `parsed.type()`、`parsed.name()`，可以把它们当作普通方法调用处理。

---

## 7. 针对 resolveTemplate 生成测试场景

当 JavaParser 能解析后，`resolveTemplate(String kind, boolean useSandbox)` 至少生成以下测试场景：

```text
- kind 为 MYSQL 且 useSandbox=false 时，应返回 mainJdbcTemplate [NORMAL]
- kind 为 MYSQL 且 useSandbox=true 时，应返回 sandboxJdbcTemplate [NORMAL]
- kind 为 DM8 时，应返回 DM8 对应 JdbcTemplate [NORMAL]
- kind 为 POSTGRESQL 时，应返回 PostgreSQL 对应 JdbcTemplate [NORMAL]
- kind 为 TDENGINE 时，应返回 TDengine 对应 JdbcTemplate [NORMAL]
- kind 为不支持类型时，应抛出 IllegalArgumentException [EXCEPTION]
- runtimeRegistry 存在配置但未返回模板时，应抛出 runtime datasource not available [EXCEPTION]
- runtimeRegistry 未配置指定数据源时，应抛出 runtime datasource not configured [EXCEPTION]
```

---

## 8. Mock 策略识别要求

`DynamicSqlExecutor` 中有很多字段依赖：

```java
private JdbcTemplate mainJdbcTemplate;
private JdbcTemplate sandboxJdbcTemplate;
private JdbcTemplate dmJdbcTemplate;
private JdbcTemplate dmSandboxJdbcTemplate;
private JdbcTemplate postgresJdbcTemplate;
private JdbcTemplate postgresSandboxJdbcTemplate;
private JdbcTemplate tdengineJdbcTemplate;
private JdbcTemplate tdengineSandboxJdbcTemplate;
private RuntimeDataSourceRegistry runtimeRegistry;
```

生成 `resolveTemplate` 测试时，Mock 策略至少识别：

```text
Mock对象：
- RuntimeDataSourceRegistry runtimeRegistry
- JdbcTemplate mainJdbcTemplate
- JdbcTemplate sandboxJdbcTemplate
- JdbcTemplate dmJdbcTemplate
- JdbcTemplate dmSandboxJdbcTemplate
- JdbcTemplate postgresJdbcTemplate
- JdbcTemplate postgresSandboxJdbcTemplate
- JdbcTemplate tdengineJdbcTemplate
- JdbcTemplate tdengineSandboxJdbcTemplate
```

其中 `runtimeRegistry` 需要生成 `when` 规则，例如：

```java
when(runtimeRegistry.getJdbcTemplate(any(), any())).thenReturn(null);
when(runtimeRegistry.hasConfig(any(), any())).thenReturn(false);
```

如果确实无法解析，不要让其他 Tab 只是空白。

应显示中文说明：

### 概要页

```text
生成失败。

原因：
当前源码使用了 JavaParser 暂不支持的语法，或当前 JavaParser 语言级别配置过低。

详细错误：
...
```

### 参数约束页

```text
未生成参数约束。

原因：
源码解析失败，无法进入参数约束抽取阶段。
```

### 测试场景页

```text
未生成测试场景。

原因：
源码解析失败，无法进入测试场景设计阶段。
```

### Mock策略页

```text
未生成 Mock 策略。

原因：
源码解析失败，无法识别依赖调用。
```

### 测试代码页

```text
未生成测试代码。

请先修复源码解析失败问题。
```

## 10. 验收标准

完成后，用 `DynamicSqlExecutor#resolveTemplate` 验证，必须满足：

1. 不再出现：

```text
Switch expressions are not supported.
Record Declarations are not supported.
```

2. 插件能正常识别：

```text
类名：DynamicSqlExecutor
方法名：resolveTemplate
返回类型：JdbcTemplate
参数：
- String kind
- boolean useSandbox
```

3. 能识别 `switch expression` 中的 `DM8`、`POSTGRESQL`、`TDENGINE`、`MYSQL`、`default` 分支；

4. 能识别 `default` 分支抛出的：

```java
IllegalArgumentException
```

5. 能识别字段依赖：

```text
RuntimeDataSourceRegistry runtimeRegistry
JdbcTemplate mainJdbcTemplate
JdbcTemplate sandboxJdbcTemplate
...
```

6. 能生成测试场景；

7. 能生成 Mock 策略；

8. 即使解析失败，也不能让后几个 Tab 完全空白，必须显示中文失败原因；

9. 生成代码中不允许出现乱码；

10. 生成代码中不允许出现中文测试方法名。
