## 3. 修复 Mock Strategy 为空的问题

当前插件只识别类字段依赖，所以对于下面这种方法：

```java
protected void doFilterInternal(HttpServletRequest request,
                                HttpServletResponse response,
                                FilterChain filterChain)
        throws ServletException, IOException {
    String user = request.getHeader(HEADER_NAME);
    DemoUserContext.set(user);
    try {
        filterChain.doFilter(request, response);
    } finally {
        DemoUserContext.clear();
    }
}
```

`Mock Strategy` 会为空。

这不满足单元测试生成需要。

请新增“接口型方法参数 Mock 识别”能力。

---

### 3.1 识别规则

在 `MockStrategyPlanner` 或 `DependencyExtractor` 中新增逻辑。

如果方法参数满足以下条件之一，则视为可 Mock 的外部依赖：

1. 参数类型是接口；
2. 参数类型名称命中常见外部依赖类型；
3. 参数类型属于 Servlet、HTTP、Filter、Request、Response、Chain 等框架接口。

MVP 阶段可以先用类型名字符串判断，不要求完整 SymbolSolver。

需要识别的类型包括但不限于：

```text
HttpServletRequest
HttpServletResponse
FilterChain
ServletRequest
ServletResponse
Request
Response
RestTemplate
WebClient
RedisTemplate
JdbcTemplate
Mapper
Repository
Client
Service
```

对于当前例子，必须识别出：

```text
HttpServletRequest request
HttpServletResponse response
FilterChain filterChain
```

并在 Mock Strategy 页显示：

```text
Mock对象：
- HttpServletRequest request
- HttpServletResponse response
- FilterChain filterChain

when规则：
- when(request.getHeader(DemoUserFilter.HEADER_NAME)).thenReturn("demo-user")

verify规则：
- verify(request).getHeader(DemoUserFilter.HEADER_NAME)
- verify(filterChain).doFilter(request, response)

never规则：
- 无
```

## 4. 修复测试代码中错误 new 接口的问题

当前生成了错误代码：

```java
new HttpServletRequest()
new HttpServletResponse()
new FilterChain()
```

这是错误的，因为这些是接口，不能直接 `new`。

请修改测试数据生成和测试代码生成逻辑。

如果参数类型是接口型依赖，或者被 Mock 策略识别为 Mock 参数，则：

1. 不生成 `new Type()`；
2. 在测试类字段区生成 `@Mock` 字段；
3. 调用被测方法时直接传入 Mock 变量名。

例如应该生成：

```java
@Mock
private HttpServletRequest request;

@Mock
private HttpServletResponse response;

@Mock
private FilterChain filterChain;
```

方法调用应该生成：

```java
demoUserFilter.doFilterInternal(request, response, filterChain);
```

而不是：

```java
demoUserFilter.doFilterInternal(new HttpServletRequest(), new HttpServletResponse(), new FilterChain());
```

## 5. 针对 DemoUserFilter 生成更合理的测试代码

对于下面这个被测类：

```java
@Component
public class DemoUserFilter extends OncePerRequestFilter {

    public static final String HEADER_NAME = "X-Demo-User";

    @Override
    protected void doFilterInternal(HttpServletRequest request, HttpServletResponse response, FilterChain filterChain)
            throws ServletException, IOException {
        String user = request.getHeader(HEADER_NAME);
        DemoUserContext.set(user);
        try {
            filterChain.doFilter(request, response);
        } finally {
            DemoUserContext.clear();
        }
    }
}
```

期望生成的测试代码至少接近下面这种形式：

```java
package com.example.dynamicdata.config;

import jakarta.servlet.FilterChain;
import jakarta.servlet.http.HttpServletRequest;
import jakarta.servlet.http.HttpServletResponse;
import org.junit.jupiter.api.Test;
import org.junit.jupiter.api.extension.ExtendWith;
import org.mockito.Mock;
import org.mockito.InjectMocks;
import org.mockito.junit.jupiter.MockitoExtension;

import java.io.IOException;

import static org.mockito.Mockito.*;

@ExtendWith(MockitoExtension.class)
class DemoUserFilterTest {

    @Mock
    private HttpServletRequest request;

    @Mock
    private HttpServletResponse response;

    @Mock
    private FilterChain filterChain;

    @InjectMocks
    private DemoUserFilter demoUserFilter;

    @Test
    void 请求头存在时_应设置用户上下文并继续过滤链() throws Exception {
        when(request.getHeader(DemoUserFilter.HEADER_NAME)).thenReturn("demo-user");

        demoUserFilter.doFilterInternal(request, response, filterChain);

        verify(request).getHeader(DemoUserFilter.HEADER_NAME);
        verify(filterChain).doFilter(request, response);
    }

    @Test
    void 请求头为空时_也应继续执行过滤链() throws Exception {
        when(request.getHeader(DemoUserFilter.HEADER_NAME)).thenReturn(null);

        demoUserFilter.doFilterInternal(request, response, filterChain);

        verify(request).getHeader(DemoUserFilter.HEADER_NAME);
        verify(filterChain).doFilter(request, response);
    }

    @Test
    void 过滤链抛出异常时_异常应继续抛出() throws Exception {
        when(request.getHeader(DemoUserFilter.HEADER_NAME)).thenReturn("demo-user");
        doThrow(new IOException("mock error")).when(filterChain).doFilter(request, response);

        org.junit.jupiter.api.Assertions.assertThrows(IOException.class, () -> {
            demoUserFilter.doFilterInternal(request, response, filterChain);
        });

        verify(request).getHeader(DemoUserFilter.HEADER_NAME);
        verify(filterChain).doFilter(request, response);
    }
}
```

说明：

1. 测试方法名可以中文，也可以英文；
2. 如果项目编码或团队规范不允许中文方法名，可以使用英文方法名，但预览说明要中文；
3. `doFilterInternal` 是 `protected` 方法，测试类与被测类同包时可以直接调用；
4. 测试方法需要 `throws Exception`，避免 `ServletException`、`IOException` 编译问题；
5. `DemoUserContext.set()` 和 `DemoUserContext.clear()` 是静态方法，MVP 阶段可以不做静态 Mock；
6. 如果后续要验证 `clear()`，需要引入 `mockito-inline` 或基于 `DemoUserContext.get()` 进行状态断言，本期先不强制。

## 6. 测试场景生成优化

当前场景只有：

```text
shouldReturnNormallyWhenInputValid [NORMAL]
shouldHandleBoundaryValues [BOUNDARY]
```

太泛泛。

请根据方法调用和参数类型生成更贴近业务的场景。

对于 `doFilterInternal` 这种 Servlet Filter 方法，至少生成：

```text
- 请求头存在时应继续执行过滤链 [NORMAL]
- 请求头为空时也应继续执行过滤链 [BOUNDARY]
- 过滤链抛出异常时应继续向外抛出异常 [EXCEPTION]
```

通用规则：

1. 如果方法中调用了 `request.getHeader(...)`，生成“Header 存在”和“Header 为空”两个场景；
2. 如果方法中调用了外部依赖方法，例如 `filterChain.doFilter(...)`，生成正常调用验证；
3. 如果外部依赖方法声明或常见语义可能抛异常，生成异常传播场景；
4. 如果没有 `if` / `throw`，不要强行生成“边界条件”这种空泛场景，而要结合参数类型和方法调用生成边界场景。

## 9. 生成测试代码的补充规则

### 9.1 对接口型参数的处理

如果参数被识别为 Mock 参数，则生成测试代码时：

* 不调用 `new Type()`；
* 不调用无参构造；
* 不使用 `null`；
* 直接使用 Mock 字段变量名。

示例：

```java
demoUserFilter.doFilterInternal(request, response, filterChain);
```

---

### 9.2 import 生成规则

如果测试代码中出现以下类型，需要自动生成对应 import：

```java
import jakarta.servlet.FilterChain;
import jakarta.servlet.http.HttpServletRequest;
import jakarta.servlet.http.HttpServletResponse;
```

如果原项目使用的是 `javax.servlet`，则应该沿用被测源码中的 import，不要强行改成 `jakarta.servlet`。

规则：

1. 优先复用被测类中的 import；
2. 如果被测类中存在 `jakarta.servlet.*`，测试类也使用 `jakarta.servlet.*`；
3. 如果被测类中存在 `javax.servlet.*`，测试类也使用 `javax.servlet.*`。

---

### 9.3 protected 方法测试规则

如果被测方法是 `protected`，生成的测试类应与被测类保持同一个 package。

例如：

```java
package com.example.dynamicdata.config;
```

这样测试类可以直接调用：

```java
demoUserFilter.doFilterInternal(request, response, filterChain);
```
