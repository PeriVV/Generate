# UnitMind 最终 UI 重构需求文档

## 1. 背景

当前 UnitMind 插件已经完成以下基础能力：

* 右侧 Tool Window 入口；
* 方法确认；
* 概要展示；
* 参数约束展示；
* 测试场景展示；
* Mock 策略展示；
* 测试代码生成；
* 写入测试文件；
* 测试文件追加 / 覆盖 / 取消逻辑；
* 测试类合并写入逻辑。

但是当前 UI 仍然存在明显问题：

1. 页面像临时调试面板，不像正式 IDEA 插件；
2. 大量内容使用纯文本或大文本框平铺；
3. 留白过大，信息密度低；
4. 表格、按钮、卡片、代码编辑器等组件使用不足；
5. 测试代码页没有真正的 Java 编辑体验；
6. 代码没有语法高亮、行号、编辑能力不明显；
7. “测试代码生成进行中...”可能一直卡住；
8. 用户无法清楚判断每一步是否成功、失败或仍在生成；
9. Tool Window 右侧宽度有限，当前布局没有针对窄窗口优化。

本次重构目标是：**把 UnitMind 从“能跑的工具窗口”升级为“像 CodeGeeX / 通义灵码一样的正式 IDEA 右侧插件面板”**。

---

## 2. 总体目标

本次 UI 重构必须达到以下目标：

```text
右侧 Tool Window 常驻
        ↓
紧凑顶部信息区
        ↓
清晰步骤条
        ↓
分步骤向导式交互
        ↓
表格 / 卡片 / 编辑器组件化展示
        ↓
测试代码可编辑、可高亮、可复制、可写入
        ↓
任何生成过程都有明确状态，不允许卡死
```

---

## 3. 总体布局要求

### 3.1 整体布局

`UnitMindToolWindowPanel` 使用 `BorderLayout`。

整体分为 4 个区域：

```text
┌──────────────────────────────────────────────┐
│ 顶部 Header 区：标题、当前方法、设置、重新分析     │
├──────────────────────────────────────────────┤
│ Stepper 步骤条区                              │
├──────────────────────────────────────────────┤
│ 主体内容区：不同步骤切换不同 Panel               │
├──────────────────────────────────────────────┤
│ 底部操作区：上一步、下一步、重新分析、写入测试文件   │
└──────────────────────────────────────────────┘
```

### 3.2 禁止继续使用整页大 JTextArea

除以下情况外，不允许继续把整页内容塞进一个 `JTextArea`：

* 失败详情；
* 日志详情；
* 临时错误堆栈；
* 测试代码编辑器暂时降级方案。

概要、参数约束、测试场景、Mock 策略、写入测试文件页面必须组件化。

## 5. 统一状态模型

### 5.1 步骤状态

新增步骤状态枚举：

```java
public enum StepStatus {
    NOT_STARTED,
    RUNNING,
    SUCCESS,
    WARNING,
    FAILED
}
```

每个步骤都必须有状态。

### 5.2 测试代码生成状态

新增测试代码生成状态枚举：

```java
public enum GenerationStatus {
    IDLE,
    RUNNING,
    SUCCESS,
    FAILED
}
```

### 5.3 状态展示规则

| 状态          | UI 显示 |
| ----------- | ----- |
| NOT_STARTED | 未开始   |
| RUNNING     | 进行中   |
| SUCCESS     | 已完成   |
| WARNING     | 有警告   |
| FAILED      | 失败    |

不允许某一步无反馈地卡住。

### 6.1 目标

顶部区要紧凑，不要占用过多高度。

### 6.2 内容结构

第一行：

右上角 `设置` 按钮打开已有的“测试数据生成配置”窗口。

按钮文本：

```text
设置
```

### 6.5 重新分析按钮

右上角 `重新分析` 按钮重新分析当前光标所在方法。

按钮文本：

```text
重新分析
```

## 7. Stepper 步骤条设计

### 7.1 步骤定义

步骤固定为：

```text
1 方法确认
2 概要
3 参数约束
4 测试场景
5 Mock策略
6 测试代码
7 写入测试文件
```

### 7.2 显示方式

不要继续显示成一长串文字。

应做成紧凑步骤条，例如：

```text
① 方法确认 ✓   ② 概要 ✓   ③ 参数约束 ✓   ④ 测试场景 ✓   ⑤ Mock策略 ✓   ⑥ 测试代码 进行中   ⑦ 写入 未开始
```

### 7.3 交互要求

1. 点击某个步骤可以切换；
2. 如果该步骤还没有数据，显示空状态提示；
3. 当前步骤高亮；
4. 已完成步骤显示 `✓`；
5. 失败步骤显示 `失败`；
6. 进行中步骤显示 `进行中`。

### 7.4 MVP 实现方式

MVP 阶段可以用 `JButton` 或 `JBLabel` 模拟 Stepper，不要求复杂动画。

### 8.2 页面布局

## 9. 概要页重构

### 9.1 当前问题

当前概要页信息太松散，且表现形式像普通文本。

### 9.2 改造目标

概要页使用：

* 方法信息卡片；
* 参数表格；
* 统计指标卡片。

### 9.3 方法信息卡片

显示字段：

| 字段    | 内容            |
| ----- | ------------- |
| 被测类   | BackupService |
| 被测方法  | backup        |
| 返回类型  | BackupResult  |

### 9.4 参数表格

使用 `JBTable`。

| 参数名     | 参数类型          | 来源   |
| ------- | ------------- | ---- |
| request | BackupRequest | 方法参数 |

### 9.5 统计指标区

使用 4 到 5 个小卡片横向排列。

| 指标     | 示例 |
| ------ | -: |
| 分支数量   |  8 |
| 参数约束   |  0 |
| 依赖数量   | 11 |
| 测试场景   |  8 |
| Mock对象 | 11 |

### 9.6 样式要求

1. 不要留大空白；
2. 卡片之间间距控制在 8px 左右；
3. 使用 IntelliJ 当前主题背景色；
4. 不写死黑白颜色。

## 10. 参数约束页重构

### 10.1 有约束时

使用 `JBTable` 展示。

表格列：

| 参数 | 类型 | 约束类型 | 异常条件 | 安全条件 | 来源 |
| -- | -- | ---- | ---- | ---- | -- |

示例：

| 参数 | 类型   | 约束类型       | 异常条件       | 安全条件       | 来源    |
| -- | ---- | ---------- | ---------- | ---------- | ----- |
| id | Long | NULL_CHECK | id == null | id != null | if 判断 |

### 10.2 无约束时

不要显示大段空白。

显示一个空状态卡片：

```text
未识别到显式参数约束

当前方法中未发现 if 判断、throw 异常分支、数值比较、非空判断等显式约束。
后续测试场景将基于参数类型、方法调用和默认测试数据规则生成。
```

### 10.3 建议区

在空状态下显示建议：

```text
建议：
- 如果该方法有隐含业务规则，可在“测试场景”步骤中手动补充。
- 如果需要调整随机测试数据范围，可点击右上角“设置”。
```

### 11.1 页面目标

测试场景页必须可编辑、可勾选、可新增。

### 11.2 表格列

使用 `JBTable`。

| 生成 | 类型 | 场景名称 | 说明 | 测试方法名 |
| -- | -- | ---- | -- | ----- |

说明：

* `测试方法名`：英文，可编辑。

### 11.3 工具栏按钮

使用 `ToolbarDecorator` 或普通按钮工具栏。

按钮：

```text

```

不允许生成：



## 13. 测试代码页重构

### 13.1 当前严重问题

当前测试代码页出现：

```text
测试代码生成进行中...
```

并且可能一直不结束。

必须修复。

### 13.2 测试代码页状态

测试代码页必须支持四种状态：

```text
尚未生成
生成中
生成成功
生成失败
```

### 13.3 空状态

尚未生成时显示：

```text
尚未生成测试代码

点击“重新生成”或进入本步骤后自动生成。
```

按钮：

```text
生成测试代码
```

### 13.4 生成中状态

生成中时显示：

```text
正在生成测试代码...
```

要求：

1. 显示 loading；
2. 禁用“写入测试文件”按钮；
3. 不能无限卡住；
4. 生成结束后必须进入成功或失败状态。

### 13.5 成功状态

生成成功后，显示代码编辑器。

必须使用 IntelliJ 代码编辑组件。

优先实现：

```java
EditorTextField
```

更优实现：

```java
EditorFactory + EditorEx
```

### 13.6 代码编辑器要求

代码编辑器必须满足：

1. Java 语法高亮；
2. 可编辑；
3. 支持滚动；
4. 显示行号；
5. 使用 IDEA 默认代码字体；
6. 写入文件时读取用户当前编辑后的内容；
7. 不能只读取初始生成内容。

### 13.7 代码页工具栏

测试代码页上方或下方增加工具栏：

```text
复制代码
恢复生成代码
重新生成
格式化代码
```

### 13.8 失败状态

生成失败时显示错误卡片：

```text
测试代码生成失败

原因：
xxx

[重新生成]
```

不要空白，不要一直显示进行中。

## 14. 修复“测试代码生成进行中”卡死问题

### 14.1 增加异步任务状态管理

生成测试代码时，不要直接在 UI 线程里阻塞。

可以使用：

* `SwingWorker`
* 或 IntelliJ `Task.Backgroundable`

推荐使用 `Task.Backgroundable`。

伪代码：

```java
new Task.Backgroundable(project, "UnitMind 正在生成测试代码", false) {
    @Override
    public void run(@NotNull ProgressIndicator indicator) {
        try {
            indicator.setText("正在生成测试代码...");
            String code = generator.generate(...);

            ApplicationManager.getApplication().invokeLater(() -> {
                testCodeStepPanel.showSuccess(code);
                updateStepStatus(TEST_CODE, StepStatus.SUCCESS);
            });
        } catch (Exception ex) {
            ApplicationManager.getApplication().invokeLater(() -> {
                testCodeStepPanel.showError(ex.getMessage());
                updateStepStatus(TEST_CODE, StepStatus.FAILED);
            });
        }
    }
}.queue();
```

### 14.2 兜底 finally

无论成功还是失败，必须退出 RUNNING 状态。

伪代码：

```java
try {
    status = RUNNING;
    ...
    status = SUCCESS;
} catch (Exception e) {
    status = FAILED;
} finally {
    refreshUi();
}
```

### 14.3 超时提示

如果生成超过 15 秒，显示提示：

```text
测试代码生成耗时较长，请稍候，或点击重新生成。
```

MVP 阶段不强制中断线程，但 UI 不能无反馈。

## 15. 写入测试文件页重构

### 15.1 页面结构

使用表单结构，不要纯文本大段展示。

分为三个卡片：

1. 目标测试类；
2. 写入模式；
3. 写入说明。

### 15.2 目标测试类卡片

显示：

| 字段   | 内容                                                             |
| ---- | -------------------------------------------------------------- |
| 测试类名 | BackupServiceTest                                              |
| 目标路径 | src/test/java/com/casc/datasync/service/BackupServiceTest.java |
| 所属包  | com.casc.datasync.service                                      |

### 15.3 写入模式

使用 `JRadioButton`。

选项：

```text
新建测试类
追加到已有测试类
覆盖整个测试类
取消写入
```

规则：

1. 如果目标测试类不存在，默认选中“新建测试类”；
2. 如果目标测试类已存在，默认选中“追加到已有测试类”；
3. 不允许默认覆盖；
4. 覆盖选项旁边显示风险提示。

### 15.4 写入说明

追加模式说明：

```text
追加模式会保留已有测试代码，并自动合并 import、@Mock 字段、@InjectMocks 字段和测试方法。
```

覆盖模式说明：

```text
覆盖模式会替换整个测试类，原有测试方法将被删除。
```

### 15.5 按钮

页面内按钮：

```text
写入测试文件
打开目标文件
```

## 16. 底部操作栏

底部操作栏始终固定在窗口底部。

按钮从左到右建议为：

```text
上一步
下一步
重新分析
写入测试文件
```

规则：

1. 第一步时“上一步”禁用；
2. 最后一步时“下一步”禁用；
3. 测试代码未生成成功时，“写入测试文件”禁用；
4. 生成中状态时，避免重复点击。

## 17. 右侧窗口宽度适配

Tool Window 宽度可能较窄，因此 UI 需要适配窄宽度。

### 17.1 表格适配

1. 表格放入 `JBScrollPane`；
2. 列宽合理；
3. 长文本列允许横向滚动；
4. 不要让表格撑爆布局。

### 17.2 内容适配

1. 右侧宽度不足时，卡片纵向排列；
2. 右侧宽度足够时，统计卡片可以横向排列；
3. 不要要求用户必须把右侧窗口拉很宽才能用。

## 18. 视觉样式要求

### 18.1 主题适配

不能写死黑色或白色。

使用：

```java
UIUtil.getPanelBackground()
UIUtil.getLabelForeground()
JBColor
```

### 18.2 字体

普通 UI：

```java
UIManager.getFont("Label.font")
```

代码编辑器：

使用 IDEA 编辑器默认字体。

### 18.3 边距

默认边距不要太大。

建议：

```java
JBUI.Borders.empty(8, 10)
```

区块之间：

```java
JBUI.emptyInsets(6, 0, 6, 0)
```

不要再用过大的 16、20、24 级别边距。

### 18.4 分组标题

统一分组标题样式：

```text
方法信息
参数信息
统计信息
Mock对象
when规则
verify规则
测试代码
写入设置
```

标题加粗，但不要太大。

## 19. 数据与 UI 分离要求

当前很多逻辑可能直接写在 UI 类中，后续会难维护。

请逐步拆分：

```text
数据生成逻辑
        ↓
GenerationResult
        ↓
UI 展示模型
        ↓
Panel 渲染
```

不要在 Panel 中直接拼接大量业务逻辑。

## 21. 测试代码写入必须使用编辑后内容

当前测试代码页改成可编辑后，写入逻辑必须读取编辑器当前内容。

流程：

```text
生成初始测试代码
        ↓
显示到代码编辑器
        ↓
```
