# Codex 修改要求：修复中文乱码、优化界面美观度、修正测试代码生成质量

当前插件界面已经改成中文，但是预览内容区出现大量 `���` 乱码，例如：

```text
���DataSourceConnectionService
���findById
���Optional<DataSourceConnection>
```

同时，界面仍然像原始文本框，不够美观；生成的测试代码也存在变量未定义、Mock 返回值不合理、中文测试方法名乱码等问题。请按以下要求修改。

---

## 1. 修复中文乱码问题

### 1.1 明确乱码原因

当前 Tab 标题和按钮中文能正常显示，但内容区出现 `���`，说明问题主要出在以下两类位置：

1. 预览内容字符串生成时已经编码错误；
2. 内容区 `JTextArea` 使用了不支持中文的等宽字体；
3. Java 源码文件或 Gradle 编译编码不是 UTF-8；
4. 读取模板、写入测试文件、复制代码时使用了系统默认编码。

必须统一处理编码和字体。

---

## 2. 统一项目编码为 UTF-8

### 2.1 Gradle 编译编码

在 `build.gradle.kts` 中增加或确认存在以下配置：

```kotlin
tasks.withType<JavaCompile> {
    options.encoding = "UTF-8"
}
```

如果项目中有 Kotlin 编译任务，也增加：

```kotlin
tasks.withType<org.jetbrains.kotlin.gradle.tasks.KotlinCompile> {
    kotlinOptions.freeCompilerArgs += "-Xjsr305=strict"
}
```

### 2.2 文件读写必须使用 UTF-8

所有读取、写入文本文件的地方，不允许使用系统默认编码。

错误写法：

```java
new FileReader(file)
new FileWriter(file)
Files.readString(path)
Files.writeString(path, content)
```

改为：

```java
Files.readString(path, StandardCharsets.UTF_8);
Files.writeString(path, content, StandardCharsets.UTF_8);
```

或者：

```java
new InputStreamReader(new FileInputStream(file), StandardCharsets.UTF_8);
new OutputStreamWriter(new FileOutputStream(file), StandardCharsets.UTF_8);
```

### 2.3 不要对中文字符串做错误转码

全项目搜索以下写法，如果存在，必须删除或修正：

```java
new String(text.getBytes())
new String(text.getBytes("ISO-8859-1"), "UTF-8")
new String(text.getBytes("UTF-8"), "GBK")
Charset.defaultCharset()
```

中文字符串应直接使用 Java 源码中的 UTF-8 字符串常量，不要反复转码。

## 3. 字体策略修改

当前预览区可能全部使用了 `JetBrains Mono` 或 `Font.MONOSPACED`。这些字体对中文支持不稳定，容易出现方块或乱码。

请修改字体策略：

### 3.1 中文说明区使用 UI 字体

以下 Tab 内容主要是中文说明，不要使用纯等宽字体：

* 概要
* 参数约束
* 测试场景
* Mock策略

这些区域使用 IDEA 默认 UI 字体：

```java
Font uiFont = UIManager.getFont("Label.font");
```

如果为空，则回退：

```java
new Font("Microsoft YaHei UI", Font.PLAIN, 14)
```

### 3.2 测试代码区使用代码字体

只有“测试代码”Tab 使用等宽字体。

优先使用：

```java
new Font("JetBrains Mono", Font.PLAIN, 13)
```

如果不支持中文或系统没有该字体，则回退到：

```java
new Font(Font.MONOSPACED, Font.PLAIN, 13)
```

但是测试代码中不要生成中文方法名，所以代码区不依赖中文字体。

## 4. 禁止生成中文测试方法名

当前生成了类似下面的测试方法名：

```java
void �����_������() {
}
```

这是不可接受的。

以后测试代码中的测试方法名统一生成英文，中文只显示在“测试场景”Tab 里。

示例：

```java
@Test
void shouldReturnDataSourceConnectionWhenIdAndOwnerIdValid() {
}
```

不要生成：

```java
@Test
void 参数合法时_应该返回数据源连接() {
}
```

### 4.1 场景展示与代码生成分离

`TestScenario` 中建议增加两个字段：

```java
private String displayNameCn;
private String methodNameEn;
```

示例：

```java
displayNameCn = "参数合法时，应返回数据源连接";
methodNameEn = "shouldReturnDataSourceConnectionWhenIdAndOwnerIdValid";
```

UI 展示中文：

```text
参数合法时，应返回数据源连接 [NORMAL]
```

测试代码使用英文：

```java
@Test
void shouldReturnDataSourceConnectionWhenIdAndOwnerIdValid() {
}
```

## 6. 修复生成测试代码中的变量未定义问题

当前生成代码中出现：

```java
Optional<DataSourceConnection> result = dataSourceConnectionService.findById(-603L, "sFtw3W6GaM");

verify(repository).findByIdAndOwnerId(id, ownerId);
```

这里 `id` 和 `ownerId` 没有定义，测试代码会编译失败。

必须改为先生成局部变量，再统一使用变量。

正确示例：

```java
Long id = -603L;
String ownerId = "sFtw3W6GaM";

Optional<DataSourceConnection> result = dataSourceConnectionService.findById(id, ownerId);

verify(repository).findByIdAndOwnerId(id, ownerId);
```

要求：

1. 方法调用参数必须来自统一的 `inputVariables`；
2. `when`、被测方法调用、`verify` 必须使用同一组变量；
3. 不允许在方法调用中直接写随机字面量，又在 verify 中使用未定义变量。

## 7. 修复 Optional 返回值 Mock 规则

当前生成了：

```java
when(repository.findByIdAndOwnerId(id, ownerId)).thenReturn(null);
```

如果仓储方法返回类型是 `Optional<DataSourceConnection>`，则不能返回 `null`。

应生成：

```java
DataSourceConnection connection = new DataSourceConnection();
when(repository.findByIdAndOwnerId(id, ownerId)).thenReturn(Optional.of(connection));
```

或者空结果场景：

```java
when(repository.findByIdAndOwnerId(id, ownerId)).thenReturn(Optional.empty());
```

### 7.1 Optional 断言规则

如果被测方法返回类型是 `Optional<T>`：

正常存在场景：

```java
assertTrue(result.isPresent());
```

空结果场景：

```java
assertTrue(result.isEmpty());
```

不要只生成：

```java
assertNotNull(result);
```

因为 `Optional.empty()` 也不是 null，`assertNotNull` 断言太弱。

---

## 8. 修复 Mock 返回值与场景不匹配问题

如果场景是“正常返回数据”，Mock 不应该返回 `null`。

错误：

```java
when(repository.findByIdAndOwnerId(id, ownerId)).thenReturn(null);
assertNotNull(result);
```

正确：

```java
DataSourceConnection connection = new DataSourceConnection();
when(repository.findByIdAndOwnerId(id, ownerId)).thenReturn(Optional.of(connection));

Optional<DataSourceConnection> result = dataSourceConnectionService.findById(id, ownerId);

assertTrue(result.isPresent());
verify(repository).findByIdAndOwnerId(id, ownerId);
```

如果场景是“未找到数据”，则生成：

```java
when(repository.findByIdAndOwnerId(id, ownerId)).thenReturn(Optional.empty());

Optional<DataSourceConnection> result = dataSourceConnectionService.findById(id, ownerId);

assertTrue(result.isEmpty());
verify(repository).findByIdAndOwnerId(id, ownerId);
```

## 11. 验收标准

### 11.1 乱码验收

完成后，界面中不允许再出现：

```text

?????
```

以下内容必须正常显示中文：

```text
类名
方法名
返回类型
参数
分支
参数约束
测试场景
Mock对象
when规则
verify规则
never规则
```

---

### 11.2 界面验收

1. 概要页不再是纯文本堆叠，应有清晰字段；
2. 参数约束页优先表格展示；
3. 测试场景页优先表格展示；
4. Mock策略页按分组展示；
5. 测试代码页使用等宽字体；
6. 所有区域有合理边距；
7. 字体不要过小，建议 13 或 14；
8. “复制代码 / 写入测试文件 / 取消”按钮靠右排列。

---

### 11.3 测试代码验收

测试代码中不允许出现未定义变量：

```java
verify(repository).findByIdAndOwnerId(id, ownerId);
```

除非前面已经定义：

```java
Long id = ...;
String ownerId = ...;
```

测试代码中不允许对 `Optional<T>` 返回：

```java
thenReturn(null)
```

应该使用：

```java
thenReturn(Optional.of(...))
thenReturn(Optional.empty())
```

测试代码中不允许生成乱码方法名：

```java
void �����_������()
```

应该使用英文方法名：

```java
void shouldReturnConnectionWhenIdAndOwnerIdValid()
```
