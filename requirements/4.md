# UnitMind 插件 UI 重构、打包部署与测试文件合并写入需求

当前插件已经具备 Java 方法识别、参数约束抽取、测试场景生成、Mock 策略生成和测试代码预览能力，但仍存在以下问题：

1. 当前 UI 仍然是弹窗式预览，不适合长期使用；
2. 希望插件安装在任意 IDEA Java 项目中后，右侧侧边栏出现 `UnitMind` 工具入口；
3. 用户点击右侧 `UnitMind` 后，以抽屉式工具窗口展示分析结果；
4. 生成过程应改成“下一步、下一步”的向导式交互；
5. 测试数据生成配置应放到工具窗口右上角设置按钮里；
6. 测试代码应该可以在插件窗口中编辑后再写入；
7. 当前写入测试文件时会直接覆盖已有测试类，导致之前函数 A 的测试代码丢失；需要改成写入前询问用户“覆盖 / 追加 / 取消”；
8. 追加时需要避免重复 import、重复 `@Mock` 字段、重复 `@InjectMocks` 字段和重复测试方法名。

本次修改目标：将插件正式命名为 `UnitMind`，将弹窗式 UI 重构为右侧 Tool Window，并修复测试文件覆盖问题。

## 3. 右侧 Tool Window 设计

### 3.1 取消以大弹窗为主的交互方式

当前 `单元测试生成预览` 弹窗可以保留为备用，但主入口应改成右侧 Tool Window。

用户期望交互方式：

```text
打开任意 Java 项目
        ↓
右侧工具栏出现 UnitMind 按钮
        ↓
点击 UnitMind
        ↓
右侧抽屉式工具窗口展开
        ↓
展示当前选中方法的分析与测试生成流程
```

---

### 3.2 注册 Tool Window

在 `plugin.xml` 中注册右侧工具窗口：

```xml
<extensions defaultExtensionNs="com.intellij">
    <toolWindow
            id="UnitMind"
            anchor="right"
            factoryClass="com.example.unitmind.ui.UnitMindToolWindowFactory"
            canCloseContents="false"/>
</extensions>
```

如果当前项目包名不是 `com.example.unitmind`，请替换为实际根包名。

---

### 3.3 新增 ToolWindowFactory

新增类：

```java
public class UnitMindToolWindowFactory implements ToolWindowFactory {

    @Override
    public void createToolWindowContent(Project project, ToolWindow toolWindow) {
        UnitMindToolWindowPanel panel = new UnitMindToolWindowPanel(project);
        ContentFactory contentFactory = ContentFactory.SERVICE.getInstance();
        Content content = contentFactory.createContent(panel, "", false);
        toolWindow.getContentManager().addContent(content);
    }
}
```

---

### 3.4 右键菜单与 Tool Window 联动

保留编辑器右键菜单：

```text
UnitMind：生成单元测试
```

用户在编辑器中选中或光标定位某个方法后，点击右键菜单时：

1. 自动打开右侧 `UnitMind` Tool Window；
2. 将当前 `Project`、`Editor`、`PsiFile`、`PsiMethod` 传给右侧窗口；
3. 右侧窗口进入第 1 步“方法确认”；
4. 用户点击“开始分析”后进入后续步骤。

不要再默认弹出大 Dialog。

```text
3. 取消
```

按钮：

```text

覆盖
取消
```

默认按钮为：

```text
追加
```

## 7. 追加写入规则

### 7.1 追加时不能简单拼接字符串

不能直接把完整测试类内容追加到文件末尾。

错误做法：

```text
已有 XxxTest.java
        +
新生成完整 XxxTest.java
```

这样会出现：

1. 重复 package；
2. 重复 import；
3. 重复 class；
4. 重复字段；
5. 重复方法；
6. 代码无法编译。

---

### 7.2 正确追加策略

追加写入时，需要将新生成测试代码拆成以下部分：

1. package 声明；
2. import 列表；
3. 测试类注解；
4. 测试类名；
5. `@Mock` 字段；
6. `@InjectMocks` 字段；
7. 测试方法；
8. helper 方法。

然后合并到已有测试类中。

---

### 7.3 import 合并规则

追加时：

1. 读取已有测试类 import；
2. 读取新生成测试类 import；
3. 合并去重；
4. 按字典序排序；
5. 保留 static import；
6. static import 与普通 import 分组显示。

示例：

```java
import java.util.Optional;

import static org.mockito.Mockito.*;
```

---

### 7.4 Mock 字段合并规则

追加时，如果已有测试类中已经存在：

```java
@Mock
private JdbcTemplate mainJdbcTemplate;
```

则不要重复追加。

判断重复依据：

```text
字段类型 + 字段名
```

即：

```text
JdbcTemplate mainJdbcTemplate
```

如果新生成字段和已有字段同名同类型，跳过。

如果字段名相同但类型不同，需要自动重命名新字段，或者提示用户冲突。

MVP 阶段建议自动重命名：

```java
private Xxx xxx2;
```

并同步修改新测试方法中的引用。

---

### 7.5 InjectMocks 字段合并规则

追加时，如果已有：

```java
@InjectMocks
private DynamicSqlExecutor dynamicSqlExecutor;
```

则不要重复追加。

如果没有，则追加。

同一个测试类中通常只需要一个被测类实例字段。

---

### 7.6 测试方法合并规则

追加时：

1. 提取新生成测试代码中的所有 `@Test` 方法；
2. 插入到已有测试类最后一个 `}` 之前；
3. 插入前加区域注释；
4. 如果方法名已存在，自动重命名。

区域注释格式：

```java
// region UnitMind generated tests for resolveTemplate

@Test
void shouldReturnMainJdbcTemplateWhenMysqlAndSandboxFalse() {
    ...
}

// endregion
```

---

### 7.7 测试方法重名处理

如果已有测试类中已经存在：

```java
void shouldReturnMainJdbcTemplateWhenMysqlAndSandboxFalse()
```

新方法自动改为：

```java
void shouldReturnMainJdbcTemplateWhenMysqlAndSandboxFalse_2()
```

如果 `_2` 也存在，则递增：

```java
_3
_4
```

---

### 7.8 同一被测方法重复生成时的处理

如果已有测试类中已经存在：

```java
// region UnitMind generated tests for resolveTemplate
...
// endregion
```

再次为 `resolveTemplate` 生成测试时，询问用户：

```text
当前测试类中已存在 resolveTemplate 的 UnitMind 生成区域，请选择：
1. 替换该方法的旧生成区域
2. 追加新的测试方法
3. 取消
```

默认选项：

```text
替换该方法的旧生成区域
```

这样避免同一个方法越生成越多。

3. 保存当前 `GenerationResult`；
4. 保存当前编辑后的测试代码；
5. 负责上一步 / 下一步跳转；
6. 调用生成服务；
7. 调用写入服务。

建议字段：

```java
private final Project project;
private Editor currentEditor;
private PsiFile currentPsiFile;
private PsiMethod currentPsiMethod;
private GenerationResult generationResult;
private String editedTestCode;
private int currentStepIndex;
```

## 12. UI 美观要求

### 12.1 不再使用全屏大文本框承载所有内容

概要、约束、场景、Mock 策略尽量使用：

1. `JPanel`
2. `JBLabel`
3. `JBTable`
4. `JBScrollPane`
5. 卡片式区域
6. 分组标题

只有“测试代码”使用代码编辑器。

### 12.2 颜色与主题

不要写死白色或黑色。

必须适配 IDEA Light / Dark 主题。

```java
UIUtil.getPanelBackground()
UIUtil.getLabelForeground()
JBColor
```

### 12.3 字体

```java
UIManager.getFont("Label.font")
```

代码编辑区使用等宽字体。

```java
JBUI.emptyInsets(8, 0, 8, 0)
```

## 13. 验收标准

### 13.1 插件部署验收

1. 执行 `gradlew.bat clean buildPlugin` 后，`build/distributions` 下生成 `UnitMind-xxx.zip`；
2. 在另一个 IDEA 中通过 `Install Plugin from Disk` 安装成功；
3. 重启 IDEA 后，右侧工具栏出现 `UnitMind`；
4. 打开任意 Java 项目后，`UnitMind` 可用。

---

### 13.2 UI 验收

1. 右侧出现 `UnitMind` 工具窗口；
2. 工具窗口不是弹窗，而是类似 CodeGeeX / 通义灵码的右侧抽屉；
3. 页面按步骤展示：

    * 方法确认；
    * 概要；
    * 参数约束；
    * 测试场景；
    * Mock策略；
    * 测试代码；
    * 写入测试文件；
4. 有“上一步 / 下一步”按钮；
5. 有设置按钮；
6. 设置按钮可以打开测试数据生成配置；
7. 测试代码区域可编辑；
8. 写入时使用用户编辑后的代码。

---

### 13.3 写入测试文件验收

1. 第一次为函数 A 生成测试，创建 `XxxTest.java`；
2. 第二次为函数 B 生成测试时，不允许直接覆盖 `XxxTest.java`；
3. 必须询问用户：

    * 追加；
    * 覆盖；
    * 取消；
4. 选择追加后，函数 A 的测试代码仍然存在；
5. 函数 B 的测试方法被插入到同一个测试类；
6. import 不重复；
7. `@Mock` 字段不重复；
8. `@InjectMocks` 字段不重复；
9. 测试方法名不重复；
10. 同一方法重复生成时，可以选择替换旧的 UnitMind region。
