# Codex 修改要求：修复 UnitMind 测试代码页为空、生成代码丢失和 DTO 参数误判为 Mock 的问题

当前 UnitMind 在分析 `BackupService#backup(BackupRequest request)` 时，前面步骤可以正常显示，但是进入“测试代码”步骤后，只显示了一个空代码编辑器，左侧只有行号 `1`，没有任何测试代码。

这说明测试代码编辑器组件已经创建成功，但传入编辑器的测试代码内容为空。请修复该问题。

---

## 1. 当前问题现象

在 UnitMind 右侧 Tool Window 中：

1. 方法确认正常；
2. 概要页正常；
3. 参数约束页正常；
4. 测试场景页正常；
5. Mock 策略页正常；
6. 测试代码页显示代码编辑器，但内容为空；
7. 写入测试文件按钮仍然可用，容易写入空文件。

当前测试代码页表现为：

```text
1
```

只有行号，没有代码内容。

---

## 2. 问题判断

这不是编辑器 UI 问题，而是数据链路问题。

可能原因包括：

1. `JUnitMockitoTestGenerator` 返回了 `null` 或空字符串；
2. `GeneratedTestFile.code` 没有正确赋值；
3. `GenerationResult.generatedTestFile` 为空；
4. 后台生成任务中发生异常，但异常被吞掉；
5. UI 状态被错误设置为 `SUCCESS`，但实际没有代码；
6. `TestCodeStepPanel.showSuccess(code)` 收到了空字符串；
7. 代码编辑器初始化时没有使用最新生成结果；
8. 生成逻辑因为当前方法复杂、Mock 策略不完整或场景为空而直接返回空。

必须逐项检查并修复。

---

## 3. 必须增加空代码保护

测试代码生成完成后必须判断：

```java
if (code == null || code.trim().isEmpty()) {
    showError("测试代码生成失败：生成结果为空。请检查测试代码生成器是否返回了有效代码。");
    updateStepStatus(TEST_CODE, StepStatus.FAILED);
    disableWriteButton();
    return;
}
```

不允许将空字符串当成成功结果显示到代码编辑器中。

---

## 4. 测试代码生成器必须有兜底输出

无论当前方法多复杂，`JUnitMockitoTestGenerator` 都不能返回空字符串。

即使无法完整生成测试，也必须生成一个最小可编辑测试类草稿。

兜底示例：

```java
package com.casc.datasync.service;

import org.junit.jupiter.api.Test;
import static org.junit.jupiter.api.Assertions.*;

class BackupServiceTest {

    @Test
    void shouldExecuteBackup() {
        // TODO: UnitMind 暂未能完整推断该方法的依赖和断言，请根据业务补充测试数据。
        BackupService backupService = new BackupService();

        BackupRequest request = new BackupRequest();

        BackupResult result = backupService.backup(request);

        assertNotNull(result);
    }
}
```

注意：如果被测类依赖字段较多、没有默认构造函数或无法直接 new，则生成 TODO 注释，但不能返回空。

---

## 5. DTO 方法参数不要默认识别为 Mock

当前 Mock 策略中把：

```text
BackupRequest request
```

识别成了 Mock 对象。

这不合理。

`BackupRequest` 是方法入参 DTO / Request 对象，通常应该构造测试数据，而不是 `@Mock`。

请修改 Mock 识别规则。

### 5.1 不应默认 Mock 的类型

以下类型默认不要作为 Mock 对象：

```text
Request DTO
Response DTO
Command
Query
Param
Form
VO
BO
DTO
Entity
Model
PO
BackupRequest
```

判断规则可以先用类型名后缀：

```text
Request
Response
DTO
VO
BO
PO
Entity
Model
Command
Query
Param
Form
```

这些类型应该进入测试数据生成逻辑，而不是 Mock 策略。

---

### 5.2 应该 Mock 的类型

以下类型可以作为 Mock 对象：

```text
Repository
Mapper
Dao
Client
Service
JdbcTemplate
RedisTemplate
RestTemplate
WebClient
ObjectMapper
RuntimeDataSourceRegistry
HttpServletRequest
HttpServletResponse
FilterChain
```

方法参数只有在明显是外部接口、框架对象或服务依赖时才 Mock。

---

## 6. 方法参数对象的生成规则

对于 `BackupRequest request` 这种方法入参对象，测试代码中应该生成：

```java
BackupRequest request = new BackupRequest();
```

如果没有无参构造函数，则生成：

```java
// TODO: BackupRequest 无法自动构造，请根据业务补充测试数据。
BackupRequest request = null;
```

不要生成：

```java
@Mock
private BackupRequest request;
```

除非它是接口或框架依赖。

---

## 7. 测试代码页状态修复

测试代码页必须有明确状态：

```java
enum GenerationStatus {
    IDLE,
    RUNNING,
    SUCCESS,
    FAILED
}
```

状态行为：

| 状态      | 页面显示          |
| ------- | ------------- |
| IDLE    | 尚未生成测试代码      |
| RUNNING | 正在生成测试代码      |
| SUCCESS | 显示代码编辑器       |
| FAILED  | 显示错误原因和重新生成按钮 |

生成结果为空时必须进入 `FAILED`，不能进入 `SUCCESS`。

---

## 8. 写入按钮状态修复

如果测试代码为空，必须禁用：

```text
写入测试文件
```

按钮启用条件：

```java
generatedCode != null && !generatedCode.trim().isEmpty()
```

并且如果用户在编辑器里把代码全部删空，再点击写入，也要拦截：

```java
if (editedCode == null || editedCode.trim().isEmpty()) {
    Messages.showWarningDialog(project, "测试代码为空，不能写入测试文件。", "UnitMind");
    return;
}
```

请在测试代码生成链路中增加日志，方便定位。

至少打印：

```text

UnitMind: scenario count = ?
UnitMind: mock count = ?
UnitMind: generated code length = ?
UnitMind: generated test file path = ?
```

如果异常：

```text

```

不要吞异常。

---

## 10. 检查 GenerationResult 数据链路

请检查以下链路：

```text
UnitTestGenerationService
        ↓
TestScenarioPlanner
        ↓
MockStrategyPlanner
        ↓
JUnitMockitoTestGenerator
        ↓
GeneratedTestFile
        ↓
GenerationResult
        ↓
TestCodeStepPanel
        ↓
EditorTextField / EditorEx
```

确保：

1. `JUnitMockitoTestGenerator` 生成的代码被写入 `GeneratedTestFile.code`；
2. `GenerationResult.generatedTestFile` 不为空；
3. `TestCodeStepPanel` 读取的是 `generationResult.generatedTestFile.code`；
4. 用户编辑后的代码保存在 `editedCode`；
5. 写入测试文件时读取 `editedCode`，不是旧的空 code。

## 12. 测试代码页成功显示标准

当用户进入“测试代码”步骤后，必须满足：

1. 不再显示空编辑器；
2. 如果成功，代码编辑器中至少有完整测试类代码；
3. 如果失败，显示错误卡片；
4. 如果代码为空，显示失败，不允许伪成功；
5. 写入按钮只有在代码非空时可用。

---

## 13. 验收标准

用 `BackupService#backup(BackupRequest request)` 验证。

必须满足：

1. “测试代码”页不再是空白；
2. 代码编辑器中至少显示一个完整的测试类；
3. 生成代码中不能把 `BackupRequest request` 默认作为 `@Mock`；
4. 生成代码中应该尝试构造 `BackupRequest request = new BackupRequest();`；
5. 如果无法构造，应生成 TODO 注释；
6. `写入测试文件` 按钮在代码为空时禁用；
7. 如果测试代码生成失败，页面显示失败原因；
8. 控制台或日志中能看到生成代码长度；
9. 不允许异常被吞掉；
10. 不允许空代码被写入测试文件。
